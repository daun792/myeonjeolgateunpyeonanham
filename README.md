# 차량 프라이버시 보호 앱

PLEOS Connect 에뮬레이터에서 프리셋과 개인정보 보호 흐름을 살펴볼 수 있는 Android 앱입니다. 차량 기본 앱이나 다른 앱을 실제로 제어하는 제품이 아니라, 앱이 소유한 예시 데이터로 기능을 보여주는 공모전용 시연 앱입니다.

## 실행 환경

- Android Studio와 Android SDK Platform 37, Android SDK Platform-Tools
- JDK 25와 저장소에 포함된 Gradle Wrapper
- Pleos Connect 2.1.0 / Android API 34 Automotive 에뮬레이터에서 화면 확인. 앱의 최소 지원 버전은 API 28입니다.

처음 빌드할 때는 Android SDK와 Gradle 의존성을 다운로드할 수 있어야 합니다. Android Studio에서 SDK 경로를 설정하거나 저장소 루트의 `local.properties`에 `sdk.dir`을 지정하세요. `local.properties`는 개발자별 설정 파일이며 저장소에 포함하지 않습니다.

## 빌드와 설치: Windows PowerShell

1. Android Studio에서 **Device Manager**를 열고 Pleos Connect 2.1.0 가상 기기를 실행합니다. 시스템 이미지가 없다면 [PLEOS 에뮬레이터 설치 안내](https://document.pleos.ai/docs/pleos-only/getting-started)를 참고하세요.
2. 저장소 루트에서 아래 명령을 실행합니다. `JAVA_HOME`과 `ANDROID_HOME`은 각 컴퓨터의 경로로 바꿉니다. `PRIVACY_APP_BUILD_DIR`은 한글 경로에서 발생할 수 있는 테스트 실행기 문제를 피하기 위해 영문 경로로 지정한 예시입니다.

```powershell
$env:JAVA_HOME = 'D:\Android\android-studio\jbr'
$env:ANDROID_HOME = 'D:\Android\sdk'
$env:PRIVACY_APP_BUILD_DIR = 'D:\Android\build\privacy-app'
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

3. 실행 중인 에뮬레이터를 확인하고 APK를 설치합니다. 기기가 여러 개이면 `emulator-5554`를 `devices`에 표시된 실제 에뮬레이터 일련번호로 바꾸세요.

```powershell
$adb = "$env:ANDROID_HOME\platform-tools\adb.exe"
& $adb devices
& $adb -s emulator-5554 install -r "$env:PRIVACY_APP_BUILD_DIR\outputs\apk\debug\app-debug.apk"
& $adb -s emulator-5554 shell am start -n com.example.vehicleprivacy/.MainActivity
```

Android Studio의 **Run** 버튼을 이용해 설치해도 됩니다. `PRIVACY_APP_BUILD_DIR`을 설정하지 않았다면 기본 APK 경로는 `app/build/outputs/apk/debug/app-debug.apk`입니다. 기존 앱과 서명 키가 다른 APK는 덮어쓰기가 거부될 수 있습니다.

## 에뮬레이터에서 살펴보기

- **프리셋:** 왼쪽 메뉴에서 프리셋을 만들고 선택하거나 설정을 변경합니다. 설정은 저장을 눌러야 반영되고, 마지막으로 선택한 프리셋은 다시 실행해도 유지됩니다.
- **보호 요청과 예시 가림:** 홈에서 보호 모드를 켜고 **앱 내부 예시 보호 확인**으로 들어가 프리셋에 따른 앱 자체 예시의 가림을 확인합니다. 홈의 상태는 실제 차량 보호 적용이 아니라 사용자의 요청 상태입니다.
- **잠시 보기:** 홈의 **차량 화면 시뮬레이션**에서 잠시 보기 버튼을 누르고 있는 동안 허용된 예시를 확인합니다. 손을 떼거나 화면 포커스를 잃으면 다시 가려집니다. 이 화면은 앱 내 모의 화면입니다.
- **보관 알림:** 홈의 **보관 알림**에서 테스트 알림을 만들고 가려진 목록과 삭제를 확인합니다. 실제 주차·보호 상태가 확인되지 않은 경우 예시 알림의 내용도 잠겨 있습니다. 실제 다른 앱의 알림을 수집하지 않습니다.
- **알림 공개 조건 시뮬레이션:** 홈의 **알림 공개 조건 시뮬레이션**에서 가상 차량 상태를 `주차`, 가상 보호 적용 상태를 `해제`로 선택한 뒤 **가상 알림 내용 보기**를 누릅니다. 두 조건 중 하나라도 다르거나 미확인이면 고정 예시가 잠깁니다. 이 화면의 가상 상태와 알림은 실제 보관함과 별개입니다.
- **동승자 알림 가림 시뮬레이션:** 프리셋 설정의 **자동 실행 → 동승자 탑승**을 켜고 저장한 후, 홈의 **동승자 알림 가림 시뮬레이션**에서 **모의 탑승**과 **모의 하차**를 눌러 앱 내부 가상 알림의 표시를 확인합니다. 변화를 명확하게 보려면 홈에서 보호 요청을 끄고 시험하세요. 보호 요청의 알림 가림이 켜져 있으면 모의 하차 후에도 예시가 가려집니다. 실제 동승자 센서나 다른 앱의 알림은 제어하지 않습니다.
- **프라이버시 점검과 접근 기록:** 저장된 프리셋의 설정을 고정 규칙으로 점검하고, 보호 요청 중 앱 내부 알림 접근 시도의 시각과 허용·차단 결과를 확인합니다. 알림 내용이나 발신자는 기록하지 않습니다.
- **가상 예시 사진:** 홈의 **가상 예시 사진 허용 목록**, 또는 프리셋 설정의 **보호 대상 → 기본 화면 세부 설정 → 가상 예시 사진 승인 관리**에서 앱이 그린 고정 예시의 허용 여부를 변경합니다. 변경은 앱 공통 설정으로 즉시 저장되며 실제 사진이나 외부 앨범에 접근하지 않습니다.
- **문장 점검과 설정 제안:** 입력 문장에서 전화번호·이메일의 일부 형식을 기기 안에서 점검하거나, 정해진 문장으로 프리셋 설정 변경을 제안받을 수 있습니다. 설정은 제안 확인과 저장을 거쳐야 반영됩니다. AI·음성 인식·TTS는 연결하지 않았습니다.
- **앱 자체 미디어 연습:** 사용자가 샘플 소리 재생을 선택한 뒤 모의 문 열림·장소 도착 버튼으로 프리셋의 일시정지·음소거 규칙을 시험합니다. 다른 앱이나 차량의 미디어는 제어하지 않습니다.

## 구현 범위와 제한

앱은 프리셋과 보호 요청 등 앱 설정을 기기 안에 저장합니다. 실제 차량의 주차·보호 적용 상태, 다른 앱의 알림·기본 화면·연락처, 차량 기본 통화나 실제 차량 미디어에는 연동되어 있지 않습니다. 설정 점검 결과나 앱 내부 예시가 실제 차량 시스템의 보호를 보증하지 않습니다.

차량 UX 제한이 감지되면 보관 알림 공개를 차단합니다. 제한이 없다는 것만으로 실제 주차가 확인되지는 않으며, 실제 상태를 확인하지 못하거나 연결이 끊기면 안전하게 내용을 잠급니다.

별도의 차량 API 신청·사용자 권한·제조사 협력이 필요한 항목은 [외부 연동·권한 확인 목록](docs/external-requirements.md)을 참고하세요. 에뮬레이터에서 수행한 PLEOS SDK 읽기 실험은 [연동 확인 사항](docs/pleos-integration.md)과 [독립 진단 프로젝트](tools/pleos-probe/README.md)에 설명합니다.
